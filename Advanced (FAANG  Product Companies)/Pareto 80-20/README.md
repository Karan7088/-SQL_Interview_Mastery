📊 Top Contributing Users (Pareto 80/20) – Advanced SQL
🚀 Problem Overview

In many real-world business scenarios, a small percentage of users contribute to the majority of revenue. This concept is known as the Pareto Principle (80/20 Rule).

This problem focuses on identifying those high-value users who collectively generate at least 80% of total revenue.

🎯 Objective

Your goal is to:

Determine total revenue generated by each user
Rank users based on their contribution
Compute cumulative revenue contribution
Identify the smallest group of users whose contribution reaches ≥ 80% of total revenue
🧠 Key Concepts Involved
Window Functions
Aggregation
Ranking
Cumulative Sum (Running Total)
Percentage Contribution
Business-driven filtering
⚠️ Rules & Constraints (Must Follow)
1️⃣ Consider Only Valid Transactions
Include only transactions where:
Status is completed
Ignore cancelled or invalid transactions
2️⃣ Aggregate Revenue at User Level
A user may have multiple transactions
Combine them into a single total revenue per user
3️⃣ Sort Users by Contribution
Users must be ordered by:
Total revenue in descending order
4️⃣ Cumulative Revenue Calculation
Compute a running total of revenue across sorted users
5️⃣ Contribution Percentage
Calculate contribution as:

cumulative_revenue / total_revenue

Express it as a percentage
6️⃣ Pareto Threshold (80%)
Select users until cumulative contribution reaches:

80% or more of total revenue

7️⃣ Include Boundary Case
The user who causes the cumulative percentage to cross 80% must be included
8️⃣ No Skipping Users
Selection must follow strict order (top → bottom)
You cannot skip users even if a later user has higher marginal impact
📊 Expected Output Format
user_id	total_revenue	cumulative_revenue	contribution_%
...	...	...	...

🔥 Common Mistakes to Avoid
❌ Using individual contribution instead of cumulative
❌ Ignoring transaction status
❌ Not sorting before cumulative calculation
❌ Excluding the boundary user crossing 80%
❌ Miscalculating total revenue
